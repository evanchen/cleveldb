# cleveldb C 编码规范

| 项目 | 内容 |
|---|---|
| 适用任务 | T003 |
| 语言/平台 | C11，仅 Linux（GCC/Clang + pthread） |
| 上游参照 | LevelDB 头文件注释风格、`port/thread_annotations.h` |
| 配套文档 | `doc/plan.md` §6、`doc/ownership.md` |

本规范约束 `include/`、`src/`、`tests/`、`tools/` 下的 C 代码。目标不是模仿 C++ 写法，而是让行为与上游一致、资源与并发可审查。示例模块见 `src/util/example.{h,c}`。

## 1. 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 文件 | 小写 + 下划线，`.h/.c` 同名 | `db_impl.c`, `write_batch.h` |
| 公开 API | `cldb_` 前缀 | `cldb_open`, `cldb_get` |
| 内部函数 | 同样以 `cldb_` 开头；文件内可见的用 `static` | `cldb_version_set_unref` |
| 类型 | `_t` 后缀，全小写 | `cldb_slice_t` |
| 枚举常量/宏 | `CLDB_` 前缀，全大写 | `CLDB_STATUS_OK` |
| 头文件保护 | `CLDB_<路径>_H_` | `CLDB_SRC_UTIL_EXAMPLE_H_` |
| 测试名 | 模块_行为 | `example_add_overflow` |

约定：

- 动词表达语义：`create` 返回新对象，`init` 初始化调用者提供的内存，`destroy` 释放对象，`free` 释放缓冲内容。
- 失败时返回状态的函数，输出参数放在最后；输入参数在前。例如：
  `cldb_status_t cldb_example_create(const char *name, cldb_example_t **out);`
- 长度用 `_size`/`_len`，数量用 `_count`，偏移用 `_offset`；不要混用。
- 返回 `bool` 的名字用 `is_`/`has_`，且必须无分配、无诊断信息。可能失败并需要原因的操作用状态返回。
- 调用者已持有锁的函数加 `_locked` 后缀；内部字段 `mutex` 明确表示保护范围。
- 局部变量短但不缩写过度；循环索引用 `i`、`j`；文件级静态变量加 `g_` 前缀。

## 2. 头文件

- 每个头文件必须自包含：单独 `#include` 即可编译，不依赖前置包含。
- 保护宏统一为 `CLDB_<路径>_H_`，例如 `src/util/example.h` 用 `CLDB_SRC_UTIL_EXAMPLE_H_`。
- include 顺序：本文件对应头 → C 标准库 → 项目公开头 → 项目内部头，组间空一行。
- 不依赖其他头文件间接提供符号：用 `NULL`/`size_t` 就显式包含 `<stddef.h>`，用 `bool` 就包含 `<stdbool.h>`。
- 不 `#include` `.c` 文件；不在头文件定义对象或分配内存。
- 只有 `include/cleveldb/` 是对外 API；`src/` 内部头不安装，测试通过私有 include 路径访问。
- 头文件里只放声明、类型、宏和极小的 `static inline` 纯函数（如 Slice 取值）。任何包含分配、I/O、锁的函数都放 `.c`。
- 无参数函数写 `(void)`；不要用空参数列表。
- `const` 表示只读，不表示所有权；所有权写注释（见第 5 节）。
- 平台条件编译只允许出现在 `src/port/` 和 Env 实现中；业务代码不得出现 `#ifdef _WIN32` 等分支。

## 3. 类型与整数

- 落盘格式、跨模块 ABI、大计数使用 `<stdint.h>` 的 `intN_t/uintN_t`；内存长度和数组索引用 `size_t`；文件偏移、序列号用 `uint64_t`。
- 不用 `long`/`unsigned long` 表达固定宽度，不用 `int` 存文件偏移。
- 所有窄化转换显式写出，并先做范围检查：
  ```c
  if (value > INT32_MAX) return CLDB_ERROR;
  int32_t narrow = (int32_t)value;
  ```
- 分配大小、偏移相加、乘法必须先检查溢出：
  ```c
  if (a > SIZE_MAX - b) { /* 失败 */ }
  size_t total = a + b;
  if (count != 0 && size > SIZE_MAX / count) { /* 失败 */ }
  ```
- 禁止依赖有符号溢出、未对齐访问和严格别名。编码/解码逐字节处理，不把 `char*` 强转成 `uint32_t*`。
- 落盘整数统一小端，由 `util/coding` 显式写字节；不要依赖主机端序。
- 枚举若进入磁盘或公开契约，显式赋值；内部枚举可以不赋值，但不得依赖默认值做持久化。
- 布尔值用 `<stdbool.h>` 的 `bool`；不要用 `int` 充当布尔返回。
- 不用位域描述磁盘结构；字节布局由编码函数负责。

## 4. 函数与错误处理

### 4.1 错误通道

- 可能失败且需要上下文的操作返回 `cldb_status_t`；示例模块已迁移到该状态类型。
- 只有“不可能失败或失败原因唯一”的纯操作才返回 `bool`；不得把关键错误吞成 `false`。
- 不把全局 `errno` 当唯一错误通道；在系统调用边界读取 `errno`，映射成状态并保留上下文。
- 错误消息只用于诊断：不参与比较、不落盘、可截断；控制流只看错误码。
- 分配失败必须向上传播，禁止静默降级或继续使用半初始化对象。

### 4.2 创建与销毁

- `_create`：成功返回对象；失败返回 NULL/状态，且输出参数置 NULL。
- `_destroy`：接受 NULL；释放后调用者不得再使用该指针；不要求重复调用安全。
- `_init`：只初始化调用者提供的内存，不接管其所有权；与 `_destroy` 成对。
- 部分构造失败时，清理已获得的资源，保持“对已初始化部分可安全 destroy”。

### 4.3 `goto cleanup`

所有可能中途失败、且持有多项资源的函数使用统一清理出口：

```c
cldb_status_t f(void) {
  cldb_status_t s = cldb_status_ok();
  char *buf = NULL;

  buf = malloc(n);
  if (buf == NULL) {
    s = cldb_status_io("out of memory", NULL);
    goto cleanup;
  }
  /* ... */
cleanup:
  free(buf);
  return s;
}
```

规则：

- 进入 `goto` 前所有资源已初始化为 NULL/0；`cleanup` 按获取的逆序释放。
- 一个函数保留一个 `cleanup` 出口；仅参数检查这类“短、纯、无资源”的前置分支可以提前返回。
- 不在 `goto cleanup` 前写业务结果；成功路径把所有结果准备好后再统一返回。
- 清理代码不能依赖可能未完成构造的字段；必要时用局部布尔标志记录初始化阶段。

### 4.4 断言

- `CLDB_ASSERT`（T107 提供）只用于内部不可能发生的不变量；外部输入、文件损坏、用户参数错误必须返回状态。
- 断言不得有副作用；Debug 构建生效，Release 不承担错误处理。
- 不直接用 `assert()`，避免与库的断言策略分叉。

## 5. 内存与所有权

- 指针是否为 `const` 不代表由谁释放；每个结构体的指针字段必须注明由谁释放、引用在什么范围内有效。
- 公开 API 返回的堆内存统一用 `cldb_free` 释放；库外不得混用 `free`/`delete`（C 版无后者）。
- 内部函数之间可以转移释放责任，但函数注释必须写明；跨模块边界默认由调用者负责释放，除非名字含 `_new_`/`_copy_` 或注释明确写了移交。
- 借用指针的生命周期窗口必须写清：调用期间、下一次修改前、直到 `destroy`。
- 回调参数默认借用；回调不得保存 Slice 指针到回调返回之后，除非文档另有说明。
- 详细规则、字段注释模板和典型场景见 `doc/ownership.md`。

## 6. 锁与并发

- 每个结构中锁字段单独命名（`mutex`、`mu`），头文件注释列出它保护的字段。
- 每个访问共享状态的函数在注释中声明锁契约，至少使用一种：
  ```c
  /* REQUIRES: example->mutex 已持有 */
  /* GUARDED_BY(example->mutex) */
  /* LOCKS: 获取并释放 example->mutex */
  ```
- 调用者必须持锁的函数加 `_locked` 后缀；加锁函数不要加该后缀。
- 锁顺序必须全局固定并写在数据结构或相关函数声明旁；不得嵌套获取两个以上的锁。
- 持锁期间不调用用户回调、不睡眠、不做文件 I/O，除非上游明确如此且有测试覆盖。
- 条件变量等待必须写成 `while (!pred)` 循环；原子操作使用 C11 `<stdatomic.h>`，并注明内存序。
- 内部引用计数在文档指定的锁/原子下操作；公开对象不使用隐式引用计数（见 `doc/ownership.md`）。
- 不使用全局可变状态、线程局部存储或“万能全局锁”掩盖设计；状态挂在实例上。

## 7. 日志与诊断

- 热路径（Get/Put/迭代器移动/块解码）不逐次打日志；只在状态转换、错误和后台事件记录。
- 不打印原始二进制 key/value；使用统一的转义函数（T116 后提供）。
- 日志文本和错误消息都不是稳定契约；测试不得断言完整文本，只断言错误码和必要前缀。
- 日志不能改变控制流；日志初始化失败不能导致数据路径失败，除非任务明确要求。

## 8. 禁用项

| 禁用 | 原因/替代 |
|---|---|
| VLA、`alloca` | 栈溢出不可控；用堆或 Arena |
| 未对齐指针强转 | x86 可能容忍，其他架构 UB；逐字节解码 |
| 严格别名违规 | 编译器优化会破坏；用 `memcpy` 或字节操作 |
| 有符号整数溢出 | UB；先检查再运算 |
| 隐式窄化/符号转换 | 用显式 cast + 范围检查 |
| `strcpy/strcat/sprintf/gets` | 无边界；用长度显式 API 或 `snprintf` |
| `atoi/atol` | 无错误检测；用 `strto*` 并检查 end/errno |
| 裸 `assert` | 与 `CLDB_ASSERT` 策略冲突 |
| 平台分支散落业务代码 | 平台差异集中在 `src/port/` 和 Env |
| C++/STL/异常/GoogleTest | 项目只使用 C11 和自有测试框架 |
| 头文件中的可变全局对象 | 线程安全与生命周期不可控 |

## 9. 格式与工具

- `.clang-format` 已固定：Google 基风格、2 空格缩进、80 列、指针右对齐（`type *name`）、include 不自动排序。
- 提交前至少运行 `clang-format` 检查本任务改动的文件；不要求格式化整个历史文件。
- 编译警告基线：`-Wall -Wextra -Wpedantic -Wshadow`；`-Wconversion` 作为逐步收敛项，CI 的专用 job 开启 `-Werror`。
- 注释挂在函数声明、数据结构声明和字段旁；不写文件级任务说明。
- 结构体字段注明用途、所有权与锁保护范围；函数声明注明用法、失败语义和返回值所有权。
- 能对应上游的声明注明 LevelDB 类型/函数（如 `Slice`、`Status::ToString`），并说明 C 版的差异及原因。
- 代码注释不写任务编号；任务背景只放在 `doc/` 文档中。
- 注释一律中文且精简；不写大段英文注释，不重复代码已表达的信息。
- 每行一条语句；`if/for/while` 必须带花括号；`switch` 覆盖所有枚举值，必要时用 `default` 兜底。
- 测试必须可重复、不依赖执行顺序、不留下临时文件；时间/并发测试使用可控注入而非 `sleep` 猜测。

## 10. 审查清单

- [ ] 头文件保护、include 顺序、自包含。
- [ ] 命名符合 `cldb_*`/`CLDB_*` 约定；输出参数在后。
- [ ] 所有分配检查失败；所有长度/偏移运算检查溢出。
- [ ] 错误路径有 `goto cleanup`，资源按逆序释放；`destroy(NULL)` 安全。
- [ ] 每个指针字段写明由谁释放；只引用时写清有效范围。
- [ ] 锁契约、锁顺序、`_locked` 后缀与代码一致；持锁时不调用用户代码。
- [ ] 未使用禁用项；没有提前实现后续任务的逻辑。
- [ ] 有边界/错误测试；ASan/UBSan 通过。
